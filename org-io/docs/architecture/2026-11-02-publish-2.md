## The handle's removed-Devices query (SDD-z3ychz)

**LLR-3ydu9e**: `OrgIo::removed_devices(&self, org_id) ->
Result<Vec<RemovedDevice>, RemovedDevicesRefused>` takes the service lock
once, finds the Persona holding the current record of `org_id`
(`record_holder_of`), and returns org-node's `removed_devices` for it
(`OrgService::removed_devices`), each entry mapped to `RemovedDevice { member_id, device_key,
acknowledged_epoch: Option<Epoch> }` in org-node's order, the epoch the
Device's entry of the Acknowledged record names. An Organisation no Persona
holds a current record of is `RemovedDevicesRefused::NotHeld { org_id }`; an
org-node refusal is `RemovedDevicesRefused::Node(error)` unchanged. It reads
no chain, takes no Device secret, sends nothing and writes nothing.
satisfies: REQ-xghnh3

## The acknowledgements' delivery (SDD-3my66m)

**LLR-u2j6u8**: in a round, the delivery takes the kept acknowledgements in
org-node's order and, for each recipient, dials its kept addresses one at a
time in the order kept — in Loopback mode only those whose endpoint
identity is the recipient's key (LLR-34tfm8) — writing the acknowledgement
and reading the verdict (LLR-fwz3tb); it stops at the first `Accepted`, and
moves to the next address on `Refused`, on any other verdict byte and on
`NotDelivered` (a failed dial, a failed stream, no byte within 10 s). When
no kept address may be dialled, in Networked mode it makes one dial by the
recipient's key alone (an empty socket list, as `send_all` does) and in
Loopback mode it dials nothing. The recipient's outcome for the round is
`Accepted`, or the last dial's result, or `NotDelivered { reason: NoAddress
}` when nothing was dialled; one recipient's outcome never stops the others.
The node's lock is not held while a dial or a verdict read is in progress.
satisfies: REQ-k6kcgd, REQ-kn8zg6
supersedes: LLR-3w22wc

*Owner ruling Q1 of 2026-11-03: option (c), as recommended.* This item
stands and supersedes LLR-3w22wc; neither a Wire change (Q1 (a)) nor no
transport change (Q1 (b)) was taken, and the Loopback residual stands.

*Note 2026-11-04 (change `worktree-org-io-publish-2`, task q1r; owner
ruling Q1' of 2026-11-04; a clarification, the ID is kept):* the one dial by
the recipient's key alone is made from the endpoint LLR-spckm6 binds for
it, with the relay server and address lookup, not from the direct-only
endpoint the round's other dials use; a direct-only endpoint has no address
lookup, so a dial by key from it could never reach the recipient. The
dial's outcome counts here as any other dial's.

**LLR-spckm6**: every acknowledgement is sent from an endpoint whose
identity is the removed Persona's own Device key, bound from that Persona's
keychain item (LLR-cns6q6), never from a fresh identity; before its first
round the delivery closes that Persona's endpoint if it is bound with a
relay and binds it again with the relay disabled and no address lookup
(`BindPlan::Direct`: Loopback mode's loopback sockets, or Networked mode's
direct sockets), and each dial that has an address is made from that
endpoint, to an address holding the recipient's Device key and only one of
its kept direct addresses, with no relay URL. A bind that fails is the
round's outcome for every recipient (`NotDelivered { reason: SenderEndpoint
}`), and the next round binds again. In Networked mode only, the one dial by
the recipient's key alone that LLR-u2j6u8 makes when no kept address may be
dialled (none kept, or none that parses) is made instead from an endpoint
of the same identity bound for that dial with the iroh relay server and
address lookup (the handle's bind plan, `BindPlan::Networked`), which
is closed once the dial's outcome is read; a bind of it that fails is that
recipient's outcome for the round (`NotDelivered { reason: SenderEndpoint
}`), the other recipients are dialled as before, and the next round binds
it again. Loopback mode never binds it.
satisfies: REQ-k6kcgd, REQ-kn8zg6
supersedes: LLR-cqr26z

*Owner ruling Q1' of 2026-11-04 (change `worktree-org-io-publish-2`, task
q1r):* LLR-cqr26z's every clause, and one relay + lookup bind for a dial by
key alone in Networked mode. Under LLR-cqr26z the dial by key of REQ-kn8zg6
went from the direct-only endpoint, which iroh refuses with "No addressing
information available" even with the recipient online and in the lookup
(o1's finding, plan "Conformance round 1"). Owner ruling D7 allows iroh's
relay server and bars only a forwarding Device, so the relay bind is
confined to the one dial that has no address; every dial that has one keeps
the direct-only bind. What the relay server and the lookup learn is
assessed in `org-io/docs/risk/2026-11-02-publish-2.md` (note of 2026-11-04).

*Note 2026-11-04 (change `worktree-org-io-publish-2`, task o2; a wording
change, the ID is kept):* "the handle's Networked plan" became "the handle's
bind plan", the one name the code gives that value (`Endpoints::bind_plan`,
the delivery's `bind_plan`); in Networked mode it is `BindPlan::Networked`.

*Note 2026-11-04 (change `worktree-org-io-publish-2`, conformance round 2;
narrows what is tested, the meaning is unchanged):* the clause "which is
closed once the dial's outcome is read" has no test. No seam can observe it:
iroh 0.98 aborts an endpoint dropped unclosed, and the relay endpoint is
dropped at the end of the dial anyway, so leaving the close out turns a
graceful close into an abort with the same report and the same receive step
at the recipient. A test below the seam is barred by TEST_GUIDELINES Seams 2.
Conformance round 2, CODE finding C2-O1.

*Note 2026-11-09 (change `worktree-org-io-publish-2`, merge review round 1,
MR1-O3; narrows what the item requires, the ID is kept):* the clause "which
is closed once the dial's outcome is read" is no longer a requirement of
this item; it is design prose of SDD-3my66m (whose note of 2026-11-04 says
the relayed endpoint is "closed after the dial"), recorded there as how
`dial_by_key` ends. Per the note above it has no test and no seam can
observe it, so this item states one testable behaviour less; every other
clause stands and its tests are unchanged.
