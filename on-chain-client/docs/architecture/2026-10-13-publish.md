# Design — mortal update writes, the forced proxy type, the pinned signatory-set read

Change `worktree-org-io-publish` (plan `docs/plans/2026-10-08-org-io-publish.md`,
tasks T14 and T16a). Requirements:
`on-chain-client/docs/requirements/2026-10-13-publish.md`.
Class C, no per-item override. The items below refine the existing writer
item SDD-yg7n55 (`2026-10-06-chain-write.md`) and the signatory-set item
SDD-rxfu6h (`2026-10-08-signatory-reads.md`), whose `traces:` lines gain the
two new requirements by dated notes. The subxt calls themselves
(`SubxtWriteOps` signing with `mortal_from_unchecked`, the client's block and
storage fetches) stay in the shell that SDD-3b8zef's recorded deviation
covers; the claims below are those a gate can reach.

## Mortal update writes (task T14; ruling D3)

**LLR-zfm3bf**: `WRITE_MORTALITY_BLOCKS` is 64 (a power of two, as a mortal
era's period must be), and `WriteWindow { birth_number: u64, birth_hash: [u8; 32] }`'s
`last_valid_block()` returns `birth_number + WRITE_MORTALITY_BLOCKS`,
saturating at `u64::MAX`: no transaction mortal from that birth block for
that period can be included in a later block (an era's first valid block is
at or before its birth, so its death is at or before this number).
satisfies: REQ-4aq8zh

*Clarified 2026-10-13 (owner ruling: keep 64 blocks).* The window bounds
only when the signed transaction can still be included in a block. It does
not bound the record the transaction writes: once included, the
Organisation's root, key and epoch stay on chain until the next write
replaces them.

Test: `on-chain-client/tests/write_pure.rs` (normal; the saturating
boundary).

**LLR-zj4jju**: `submit_update(ops, signatory, co_signatories, contract,
proxy, root, key, expected_epoch, window: WriteWindow)` passes
`Some(window)` to its one `WriteOps::dispatch`, and `genesis` passes `None`
to each of its dispatches; `SubxtWriteOps::dispatch` signs a `Some(window)`
dispatch mortal from the window's birth block for `WRITE_MORTALITY_BLOCKS`
and a `None` dispatch with subxt's default parameters.
satisfies: REQ-4aq8zh

Test: `on-chain-client/tests/write_compose.rs` (the window reaches the
dispatch; genesis passes none), through the gated `WriteOps` substitute; the
signing clause is shell.

*Note 2026-10-13 (task gate1fix; robustness).* Abnormal case added in
`write_compose.rs`: a mortal dispatch that is refused, or recorded only as a
pending approval, is reported and never retried — in particular not without
its window — so exactly one dispatch is made, carrying the window. A window
whose birth block cannot be read never reaches this item (`write_window`
is the client's shell; org-io writes nothing when that read fails, tested
in org-io's `a_failed_window_read_writes_nothing`), and a birth block the chain refuses is the signing
clause's, shell.

## The forced proxy type (task T16a; ruling D4)

**LLR-59kxsr**: `proxied(proxy, call)` builds `Proxy.proxy` with `real` the
`Id` of the proxy's thirty-two bytes, `force_proxy_type` `Some(Any)` (the
variant named `Any`, which the dynamic encoder resolves against the
runtime's metadata, never a constant index) and `call` the call given; and
`map_account_call()` builds `Revive.map_account` with no arguments.
satisfies: REQ-aat4yt, REQ-6jefu2
supersedes: LLR-ywhd23

Test: `on-chain-client/tests/write_pure.rs` (new tests carry both IDs).

*Note 2026-10-13 (task gate1fix; robustness).* `write_pure.rs` also encodes
the proxied call against a minimal runtime type registry built from derived
`TypeInfo`: where the runtime gives `Any` index 5 it encodes exactly as that
runtime's own `Some(Any)` (normal), and against a proxy type with no `Any`
it does not encode (abnormal) — so it is refused rather than forced to
another type, and a call that does not encode is never signed or dispatched
(the encode-before-sign step in `SubxtWriteOps` is shell).

## The pinned signatory-set read (task T16a; rulings D4, D5)

**LLR-n2vx5q**: `decode_proxy_definitions(bytes: &[u8]) -> Result<Vec<ProxyDefinition>, SignatorySetError>`
decodes the SCALE value `(BoundedVec<ProxyDefinition<AccountId32, ProxyType, u32>>, u128)`
— a compact length `n`, then `n` definitions of a 32-byte delegate, a
one-byte proxy type and a four-byte little-endian delay, then a 16-byte
deposit — and returns the `n` definitions `{ delegate, proxy_type, delay }`
in stored order; a value with trailing bytes, too few bytes, or a length
prefix larger than the bytes that follow is `Malformed`, and no input panics
or allocates more than the input's length allows.
satisfies: REQ-b8x2py
supersedes: LLR-a9bb7b

Test: `on-chain-client/tests/signatory_set_decode.rs` and the fuzz target
`fuzz_signatory_set` (new tests carry both IDs).

**LLR-sc79gq**: `OrgRegistryClient::signatory_set(org) -> Result<SignatorySet, ClientError>`
resolves the latest finalised block once, and reads `Revive.OriginalAccount`,
`Proxy.Proxies` (only when the account is mapped) and the index of the
variant named `Any` of the runtime's proxy type from that one block; it
returns `SignatorySet { original_account, definitions, any_proxy_type }`,
and a typed error when a read fails, a value does not decode, or no `Any`
variant exists.
satisfies: REQ-b8x2py

Test: a source scan in `on-chain-client/tests/signatory_set_decode.rs`
(`signatory_set`'s body resolves the block once and passes it to every
read); the index lookup over metadata is tested where a metadata fixture
exists, else recorded as shell.

*Note 2026-10-13 (task T16a).* The crate has no metadata fixture, so the
`Any` lookup (`any_proxy_type_index` in `client.rs`: the type of
`Proxy.create_pure`'s `proxy_type` argument, with the variant named `Any`
encoded against it by subxt's dynamic encoder and its one byte taken as the
index; no such argument, a failed encoding or a longer encoding is
`SignatorySetError::NoAnyProxyType`, a `ClientError::Decode`) is shell,
under SDD-3b8zef's recorded deviation, exercised only against a chain. The
source scan covers that the lookup takes the pinned block.

*Note 2026-10-13 (task gate1fix; supersedes the T16a note's "shell" for the
lookup and the assembly; coverage and robustness).* The chain-free logic left
`client.rs` for `write/signatory_set.rs`, behaviour unchanged:
`any_proxy_type_index(&subxt::Metadata) -> Result<u8, SignatorySetError>`
(the lookup above), and `read_signatory_set(source, admin, any_proxy_type)`
over a `SignatorySetSource` (the two reads, `Proxy.Proxies` only for a
mapped account, and the decoding; a failed read is the source's error, an
undecodable value the source's decode error). `signatory_set` resolves the
block, looks `Any` up in that block's metadata and reads through
`PinnedBlock`, a source whose every fetch is at that block; only that is
shell. No metadata fixture is needed: `signatory_set_decode.rs` builds
`subxt::Metadata` from a minimal v16 metadata with derived `TypeInfo`, and
tests the lookup (normal: `Any` at index 0 and at index 5; abnormal: no
`Proxy` pallet, no calls, no `create_pure`, no `proxy_type`, no `Any`, an
`Any` with a field, a proxy type that is not an enum — each
`NoAnyProxyType`), the assembly over a fake source (normal: mapped,
unmapped, no proxies stored; abnormal: either read failing, either value
undecodable, nothing read after the first failure), and the entries' storage
names. The source scan now pins that `signatory_set` hands the one block to
both the lookup and the source.
