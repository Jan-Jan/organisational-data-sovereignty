# Requirements — mortal update writes and the pinned signatory-set read

Added 2026-10-08 by change `worktree-org-io-publish` (stage S3b-io; plan
`docs/plans/2026-10-08-org-io-publish.md`), on the owner's rulings D3, D4
and D5 of that day. Consumer: org-io (its unknown-write settlement and its
own-admin check), named here in prose only: this unit does not depend on
org-io. Both are `satisfies: derived`, assessed in
`on-chain-client/docs/risk/2026-10-13-publish.md`.

**REQ-4aq8zh**: The software shall provide a read of the latest finalised
block's number and hash (a write window), shall submit each update write
through an Organisation's proxy as a transaction mortal from that block for
`WRITE_MORTALITY_BLOCKS` blocks, and shall report for the window the last
block number at which such a transaction can be included, so that a caller
that stopped waiting for the write can learn from a later finalised block
that it can no longer execute.
satisfies: derived
exported: yes

Owner ruling D3 (2026-10-08): discarding an update whose write's outcome is
unknown is refused until the transaction's mortality has passed and a
finalised block shows the record's epoch; on-chain-client sets an explicit
mortality and returns it. Before this, the writer used subxt's default
(mortal for 32 blocks when block information is available, otherwise
immortal), which no caller could see. *Clarified 2026-10-13 (owner ruling:
keep `WRITE_MORTALITY_BLOCKS` at 64):* the mortality bounds only how long a
signed transaction can still be included; the state it writes stays on
chain until the next write replaces it. Genesis writes keep the default: the
consumer does not settle them.

**REQ-b8x2py**: The software shall provide one read, at one finalised block,
of the account pallet-revive maps an Organisation's H160 to
(`Revive.OriginalAccount`) and of that account's proxy definitions
(`Proxy.Proxies`), returning the mapped account or nothing, every definition
with its delegate, proxy type and delay in stored order, and the index of the
runtime's `Any` proxy type taken from that block's metadata; and an error
when either read fails, a stored value does not decode, or the runtime's
proxy type has no `Any` variant.
satisfies: derived
exported: yes
supersedes: REQ-v8jczx

Owner rulings D4 and D5 (2026-10-08; org-io's report on the admin rule, and PR-ksm2ua): the consumer's
admin rule needs each definition's type and delay, and the two values must
describe one chain state. REQ-8p2veg's own read is unchanged and stays.

*Corrected 2026-10-13 (unmerged draft; review round 2, finding-4):* the
last sentence is no longer true. REQ-8p2veg was narrowed the same day
(review round 1, finding-8): its own read, `OrgRegistryClient::original_account`,
was removed unused, and the mapped account it names is now provided only
through this item's one pinned read (`signatory_set`).
