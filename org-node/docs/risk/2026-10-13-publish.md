# Risk — a Persona's keys are its own (expectation)

Run 2026-10-13 for change `worktree-org-io-publish`, against this unit's
acceptability matrix (`README.md`).

### REQ-and2gz (no key reuse across a Person and its memberships)

Mitigates linkability: a Persona key equal to the Person's key or to
another membership's would let any Member of either Organisation link the
individual's memberships, defeating the separation a Persona exists for — an
identity exposure in the deployments this project serves. Today the risk is
latent, not present: `create_persona` draws fresh seeds for every Persona,
so reuse needs a code change or an import path that does not exist yet (the
roadmap's "(later)" key-import choice would create one). Until a providing
unit checks it, the control is the fresh generation alone. No new hazard is
introduced by recording the expectation.
