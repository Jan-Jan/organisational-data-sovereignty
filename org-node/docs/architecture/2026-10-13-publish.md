# Design — a founding drops its Persona's other genesis updates

Change `worktree-org-io-publish` (plan `docs/plans/2026-10-08-org-io-publish.md`,
task T15d). Owner ruling of 2026-10-13: provisional updates are accepted and
discarded in the background; when one is accepted, the others are discarded.
For an Organisation's updates, every commit already discards the others
(LLR-mkj4bz). A genesis update has no Organisation yet, so that rule does not
reach a Persona's earlier, failed foundings; this item does. It sits under
SDD-af5vnt with LLR-mkj4bz's parent, REQ-uv3v5w. Class C, the unit's class.

**LLR-pk6mhv**: when `commit_genesis` commits a founding for a Persona, it
also removes every other stored provisional update
`ProvisionalTarget::Genesis(persona_id)` names, each with the Organisation
private key it holds, in the same store save; a refused `commit_genesis`
removes none, and the genesis updates of every other Persona are left as
they were.
satisfies: REQ-uv3v5w

*Clarified 2026-10-14 (master's S3b-io part 1 merged into S4,
`worktree-org-io-transport`; hybrid rule, a clarification):* org-node saves
nothing since S4's task T3: "in the same store save" reads "in the one
`StoreWrite` the commit returns", sealed from the Persona's changed copy;
a Persona's genesis updates are all in its own store, which that write
replaces, and every other Persona's store is untouched.

*Rewritten in place 2026-10-13 (unmerged draft; owner ruling of that day,
background discard).* It read: "`OrgService::discard_genesis_updates(rng,
persona_id) -> Result<usize, OrgNodeError>` removes every stored provisional
update `ProvisionalTarget::Genesis(persona_id)` names … saves the store once
before returning, and returns how many it removed; when it names none … it
returns `NoProvisionalUpdate` …" (satisfies REQ-hhva9d). The public method
is removed: org-io offers no genesis discard. *Deleted the same day:* the
low-level requirement of `OrgService::held_provisional_updates`, a
by-reference listing for org-io's held-update list (task T15c), which the
ruling removes; its test is deleted with it, and its ID is removed from
this note, as check-trace requires of a deleted item (plan, task T15d).

Test: `org-node/tests/commit_paths.rs` (normal: a founding after a failed
one leaves no genesis update of that Persona; abnormal: a refused founding
removes none, and another Persona's genesis update is kept).
