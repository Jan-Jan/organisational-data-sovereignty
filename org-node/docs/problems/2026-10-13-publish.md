# Problems — a reconcile whose save fails, from S3b-io's review

Recorded 2026-10-13 by change `worktree-org-io-publish` (stage S3b-io,
part 1), review round 2, finding-3, on the owner's ruling of that day to
book it here rather than fix it in org-io.

**PR-jgvf3b**: `OrgService::reconcile` puts the committed store into memory before it saves (`*self.store.data_mut() = store.clone(); self.store.save(rng)?;`, `org-node/src/service.rs:1019-1021`), so when the save fails it returns `Err` with memory already ahead of disk; org-io's reconcile then loses the send of a late write's update to the Device its submission named, because every later reconcile finds the record in step and has no commit outcome to send.
affects: LLR-fm38ww, SDD-8cpyfa
opened: 2026-10-13
status: open

Where it bites: org-io's reconcile of an Organisation with a chain write
whose outcome was unknown, when the state read shows that write executed
(org-io's unknown-write requirement and its reconcile design item, which
send the committed update to the Device the submission named; org-io
exports neither, so they are named here by description). With the store
file unwritable, org-node's reconcile commits in memory, fails the save and
returns `Err`; org-io reports the Organisation refused. The next reconcile
returns `InStep`, so nothing is sent. Had org-io kept its unknown write on
that `Err`, its next settle would have found the record past the write's
expected epoch and reported the executed write as not executed — so org-io
cannot repair this on its side; org-node must not report a failure with the
commit already in memory.

Reproduction recipe: the probe test kept from that review,
`r2fix-finding3-probe-test.rs` (in the change's session scratchpad, to be
pasted into `org-io/tests/publish_path.rs`): an admission whose write lands
after its timeout (`write_lands_then_hangs`), the store file made read-only
(mode 0o400) around `OrgIo::reconcile`, which returns `Refused`; the store
made writable again; a settle and a reconcile follow (`InStep`), and the
recorded Device never receives the update (its receive times out).

Same class as PR-jav8zn (`2026-10-08-save-after-mutate.md`: `commit_genesis`,
`commit_update`, `discard_provisional`), whose fix outline applies (save a
copy, swap memory only on success); booked separately because PR-jav8zn's
scope is set by owner ruling and does not name `reconcile`. For S4 to fix
with that class (its tasks T3 and T9, where org-node returns the store
change instead of saving).
