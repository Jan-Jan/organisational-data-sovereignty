# Design — key and device-set constructors under the parse rule

Low-level requirements for bringing the public key types and the device key
set under the parse-at-the-system-edge rule
(`docs/adr/2026-10-04-parse-at-the-system-edge.md`), the follow-up the
2026-10-04 status note in `org-members/AGENTS.md` names. Both belong to
SDD-4yr9ge (`2026-09-17-decomposition.md`), which owns `types.rs`.

## SDD-4yr9ge — Member record and validation

**LLR-k6dhz7**: `DevicePublicKey::parse(&[u8; 32])` and
`PersonPublicKey::parse(&[u8; 32])`, `person`'s constructors that org-members
re-exports, and the `TryFrom<[u8; 32]>` impls that delegate to them, accept
exactly the bytes their `Deserialize` accepts (LLR-z954wj's rule for a
DevicePublicKey, LLR-a645bx's for a PersonPublicKey), keep the bytes as
given, and refuse any other with `person::IdentityError::InvalidDeviceKey` or
`InvalidPersonKey`, which `From` maps to `OrgMembersError::InvalidDeviceKey`
or `InvalidPersonKey`.
satisfies: derived

*Amended 2026-10-05 (owner answer Q4 to docs/plans/2026-10-05-switch-trim.md;
written by change `worktree-person-shared-types`).* This item named
`P2pMemberKey::parse` and `P2pDeviceKey::parse`, accepted exactly the bytes
that decompress to an Edwards point, refused any other with
`OrgMembersError::InvalidKey`, and said neither refuses a small-order or
non-canonically encoded key (owner ruling 2026-10-04; PR-b7khyw). The change
that switches org-members to `person`'s identity types deletes both types.
The constructors still accept exactly what decoding accepts, but decoding no
longer accepts a small-order or non-canonical key, so the last clause and the
single `InvalidKey` no longer held. The owner ruled that retired behaviour is
amended in place, so a replacement item that stated this text was withdrawn
before merge and its text folded in here.

**LLR-t3p9zk**: `P2pDeviceSlots::parse(Vec<P2pDeviceKey>)` (renamed from
`new`) holds the keys sorted, refuses more than `MAX_DEVICES` keys with
`DeviceSlotsFull` and a repeated key with `DuplicateDevice`, and accepts the
empty list.
satisfies: REQ-xdx2c2
superseded-by: LLR-st6j2r
