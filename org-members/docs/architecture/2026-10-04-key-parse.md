# Design — key and device-set constructors under the parse rule

Low-level requirements for bringing the public key types and the device key
set under the parse-at-the-system-edge rule
(`docs/adr/2026-10-04-parse-at-the-system-edge.md`), the follow-up the
2026-10-04 status note in `org-members/AGENTS.md` names. Both belong to
SDD-4yr9ge (`2026-09-17-decomposition.md`), which owns `types.rs`.

## SDD-4yr9ge — Member record and validation

**LLR-k6dhz7**: `P2pMemberKey::parse(&[u8; 32])` and `P2pDeviceKey::parse`,
and the `TryFrom<[u8; 32]>` impls that delegate to them, accept exactly the
bytes that decompress to an Edwards point — the bytes their `Deserialize`
accepts — and refuse any other with `OrgMembersError::InvalidKey`; neither
refuses a small-order or non-canonically encoded key (owner ruling
2026-10-04; PR-b7khyw).
satisfies: derived

**LLR-t3p9zk**: `P2pDeviceSlots::parse(Vec<P2pDeviceKey>)` (renamed from
`new`) holds the keys sorted, refuses more than `MAX_DEVICES` keys with
`DeviceSlotsFull` and a repeated key with `DuplicateDevice`, and accepts the
empty list.
satisfies: REQ-xdx2c2
