# Design — key and device-set constructors under the parse rule

Low-level requirements for bringing the public key types and the device key
set under the parse-at-the-system-edge rule
(`docs/adr/2026-10-04-parse-at-the-system-edge.md`), the follow-up the
2026-10-04 status note in `org-members/AGENTS.md` names. Both belong to
SDD-4yr9ge (`2026-09-17-decomposition.md`), which owns `types.rs`.

## SDD-4yr9ge — Member record and validation

**LLR-k6dhz7**: `DevicePublicKey::parse(&[u8; 32])` and
`PersonPublicKey::parse(&[u8; 32])`, `person`'s constructors that org-members
re-exports, and the `TryFrom<[u8; 32]>` impls that delegate to them, accept
exactly the bytes their `Deserialize` accepts (LLR-z954wj's rule for a
DevicePublicKey, LLR-a645bx's for a PersonPublicKey), keep the bytes as
given, and refuse any other with `person::IdentityError::InvalidDeviceKey` or
`InvalidPersonKey`, which `From` maps to `OrgMembersError::InvalidDeviceKey`
or `InvalidPersonKey`.
