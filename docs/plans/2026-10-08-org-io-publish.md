## 5. PR-wk7zwq — what "admin" should mean (open decision D4)

**The defect.** REQ-f3eu9n and LLR-vyd5d3 report `Admin` when any of the proxy account's delegates equals the controller (the node's own account, or the threshold-1 multisig of it and its co-signers). on-chain-client's `decode_proxy_delegates` (`on-chain-client/src/write/signatory_set.rs`; LLR-a9bb7b, REQ-v8jczx) decodes `Proxy.Proxies`' value `(BoundedVec<ProxyDefinition<AccountId32, ProxyType, u32>>, u128)` — 32-byte delegate, 1-byte proxy type, 4-byte delay per definition, then the deposit — and keeps only the delegate.

**What the chain does with those two fields** (pallet_proxy). Every org-io write is `Multisig.as_multi_threshold_1` of `Proxy.proxy { real: Id(proxy), force_proxy_type: None, call }` (`on-chain-client/src/write/proxy.rs:23`). `proxy` finds the definition with `find_proxy(real, delegate, force_proxy_type)` — with `force_proxy_type: None`, the **first** definition in stored order whose delegate is the caller, whatever its type — then refuses with `Unannounced` unless that definition's `delay` is zero, then dispatches the call through the definition's `proxy_type` filter (`InstanceFilter`), which refuses a call the type does not permit. Stored order is the definitions' sorted order (`ProxyDefinition` orders by delegate, then proxy type, then delay). The pure proxy is created by `Proxy.create_pure { proxy_type: Any, delay: 0, index: 0 }` (`proxy.rs:8`), so the founding definition is `(controller, Any, 0)`; only a call dispatched *as the proxy* (i.e. by an existing admin) can add or remove definitions. So a delegate that cannot write today exists only if an admin added a second definition for the controller with a restricted type or a delay, or replaced the original — deliberate on-chain administration, not an attack from outside the signatory set. The admin check then says `Admin` where every write would be refused (`Unannounced`, or the filter's `CallFiltered` on `Revive.call`). The proxy-type byte is runtime-specific: `Any` is variant 0 on Polkadot/Kusama/Asset Hub runtimes, but the index must come from the runtime's metadata, not a constant. "Admin" in org-io and on-chain-client's docs (on-chain-client `docs/CONTEXT.md`, "Organisation admin"; REQ-f3eu9n; SDD-f4khqn) means "a signatory of the multisig that controls the pure proxy", which says nothing about type or delay.

**Options for the owner.**

1. **Mirror the writer exactly (recommended, with 2's write change).** `Admin` exactly when the definition `Proxy.proxy` would use for the controller permits an immediate `Revive.call`: proxy type `Any` (resolved from metadata) and delay 0. Today, with `force_proxy_type: None`, that is "the first stored definition naming the controller is `(Any, 0)`". on-chain-client returns definitions `(delegate, proxy_type name, delay)` in stored order instead of delegates; org-io's rule reads them.
2. **Change the writer to force `Any`** (`force_proxy_type: Some(Any)`), so the chain picks the controller's `Any` definition wherever it sorts, and the rule becomes "some definition is `(controller, Any, 0)`". Removes the order dependence of 1 (a second, restricted definition sorted first would otherwise make the writer fail although an `Any`/0 definition exists). Costs a change to an on-chain-client write item (the `Proxy.proxy` call shape, `on-chain-client/docs/architecture/2026-10-06-chain-write.md:174`) and its golden encoding, if any.
3. **Report the restriction as its own status.** Keep `Admin`/`NotAdmin` for the clean cases and add `DelegateCannotDispatch { delay, proxy_type }` (public data) when the controller is a delegate only through restricted or delayed definitions, so the app can say why the node cannot write rather than "not an admin". Combinable with 1 or 2.
4. **Allow non-`Any` types that permit `Revive.call`** (e.g. a runtime's `NonTransfer`). Needs a per-runtime list of which types pass the filter for `Revive.call`, which the chain does not expose; brittle. Not recommended.
5. **Leave the rule and accept the misreport** (nothing the check gates can bypass the chain, which refuses the write anyway). Then the limit-setting command (T16c) would let a node set limits it cannot back with chain authority. Not recommended: the check's point is to gate admin-only settings.

**Recommendation: 2 + 3.** The writer forces `Any`; `Admin` exactly when a definition `(controller, Any, 0)` exists; `DelegateCannotDispatch` when the controller is a delegate only with another type or a non-zero delay; `NotAdmin` otherwise; a failed read stays an error. **Hybrid-rule consequences** (all merged items, all a change of meaning): new superseding IDs for REQ-f3eu9n and LLR-vyd5d3 (org-io), REQ-v8jczx and LLR-a9bb7b (on-chain-client, the read returns definitions), and the `Proxy.proxy` call item in on-chain-client; new red-first tests carry both old and new IDs; green tests are not re-annotated; PR-wk7zwq resolved by T16a with a reproducing test (a `(controller, NonTransfer, 0)` or `(controller, Any, 10)` definition: `Admin` before, not `Admin` after).

**PR-ksm2ua (open decision D5),** booked with it: the two reads each resolve "latest finalised" separately. Options: (a) read both at one pinned finalised block hash (on-chain-client gains one combined read, `signatory_set(org) -> (Option<AccountId>, Vec<ProxyDefinition>)` at one block; superseding items for REQ-8p2veg/REQ-v8jczx's "each at the latest finalised block", or a new combined requirement); (b) state why the split is harmless (a definition change between two finalised blocks is itself admin action, and the answer only gates a local setting) and resolve as accepted. **Recommendation: (a)**, done in T16a with D4's change of the same read, so the read is changed once.
