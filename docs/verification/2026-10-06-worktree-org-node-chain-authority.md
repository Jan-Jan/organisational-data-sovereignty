## What was wrong, and what was built

PR-szkat6 found that org-node verified every Envelope under `org_pub_key`,
which genesis set to the founding Member's key, while the design intends
`org_pub_key` to be the public half of an Organisation key pair every Member
holds. The owner stated the model (2026-10-05): the right to change an
Organisation lies in its on-chain multisig proxy; org-node and org-members have
no concept of an administrator; an update is checked against the chain alone.
Master's person-types switch (`5f7c177`) had already made the Envelope
unsigned and the Organisation key an X25519 pair; this change, built on it,
carries the rest of the owner's change 1 (the X25519 key pair's distribution is
change 3 and leaves PR-szkat6 open):

- org-node: no sender check on any path; no `admin_member_key` or
  `admin_device_key`; Invites, Join requests and pending Invites removed
  (the app owns the exchange); no chain write (`chain_write/`, `ceremony.rs`
  and the sr25519 multisig key gone; it reads the chain only). Create, admit
  and revoke build provisional updates, persisted in the encrypted store,
  several per Organisation, bounded at 1 MiB per Organisation (REQ-xs4ab8,
  REQ-fwfku9), discardable (REQ-hhva9d); a node commits its own update only
  after it verifies against the chain (REQ-tqap3r), discarding what it orphans
  (REQ-uv3v5w), and commits never wait on a send. Every chain-free check runs
  before the single chain read (REQ-f2k4tr/RC-mj6gjq); a first admission is
  read against the chain only for an expected (Organisation, invite id)
  (REQ-8amu2a/RC-2ferct) and commits only if the record lists one of this
  node's own unbound Personas (REQ-kt877x, REQ-yp75u9); own removal deletes
  the record on every commit path (REQ-uxv2x2).
- on-chain-client: the chain writer behind `write` (SDD-yg7n55): genesis
  ceremony and update submission (REQ-6jefu2, REQ-aat4yt), with a proxied
  inner-call failure reported as a typed error (LLR-24mwew).
- app: submits each provisional update through on-chain-client within a 90 s
  bound, then asks org-node to commit and send (REQ-nfr3n2); the invitation
  exchange with a random invite id kept as an (Organisation, invite id) pair
  (REQ-prjja8, REQ-tcutr6, REQ-65xqp8, REQ-yazum3); a confirmed warning
  before a reply reveals the Persona's name details (REQ-ab2mfz/RC-wzb48r);
  unbound Personas only (LLR-rt8gdz).
