# Design — values in, values out: org-node reads no chain

Low-level requirement for change `worktree-org-io-create` (stage S2), owner ruling B of 2026-10-06:
org-node meets org-io by values in, values out. org-io reads the chain and
hands org-node each Organisation state as a value; org-node names no chain
library and holds no chain seam. The item below sits under SDD-ueh4tm (the
boundary between the user stories and the chain, in
`2026-10-03-decomposition.md`, amended 2026-10-08 to say that boundary is now
the state value each chain-judging operation takes) and refines an earlier form of LLR-rr558z,
the requirement SDD-ueh4tm and that item already served: the Organisation's
state comes from a path the sender does not control. It is that item's only
new low-level requirement in this change.

## Added 2026-10-08: a by-reference query of the held updates

*Added 2026-10-08 (S2 review round 4, finding 2).* org-io's pre-write guard
asked whether org-node holds the update it is about to write by taking
`provisional_updates(org_id)`, which clones every held `ProvisionalUpdate`
with the Organisation private key inside its `ProvisionalChange`, to compare
four public fields. `OrgPrivateKey` is never wiped, so each copy is an
unwiped secret, against the ruling that keys only move. This item gives the
guard a query that copies nothing; it is the second new low-level
requirement of this file, beside the item LLR-7en38k replaced.
