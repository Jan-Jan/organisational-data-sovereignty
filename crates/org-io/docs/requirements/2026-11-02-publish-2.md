## The removed Devices of an Organisation (T16g)

**REQ-xghnh3**: The software shall give the app, for an Organisation one of
its Personas holds a current record of, every Device that Persona's store
holds as revoked, with the MemberId it was listed under and whether a
Removal acknowledgement from it is kept there (and if so the epoch it
names), reading no chain, sending nothing and writing nothing.
satisfies: derived

org-node's list of the Devices a store holds as revoked, passed through: org-io judges nothing. The
acknowledgement itself is kept by org-node's receive path (its acknowledged-record requirement) and
written by the store change org-io's receive step already writes; this
requirement adds only the query.

## Reaching the delivering Device (T16c4)

**REQ-kn8zg6**: The software shall, in Networked mode, when an
acknowledgement's recipient has no kept endpoint address that may be dialled,
send it to that recipient by its Device key alone, under the Persona's own
Device key as REQ-k6kcgd states, and report the outcome as for any other
recipient; in Loopback mode it shall report such a recipient not delivered
for want of an address, as before.
satisfies: derived

*Owner ruling Q1 of 2026-11-03: option (c), as recommended.* Owner ruling R2 makes the Device the removal was
received from the first recipient (org-node's delivering-Device requirement). Domain-api sends
only to addresses kept per Device key and never to an inbound connection's
source, and neither a revocation notice nor Organisation information nor an
organisation answer carries the sender's addresses (`crates/org-node/src/wire.rs`),
so the removed Device keeps an address for the delivering Device only when
its address book holds one: the issuer of its own Invite, or a Device whose
organisation request reached it. A notice answered by a Member this Device
reached through discovery, and an epoch sent by an Admin Device other than
its Invite's issuer, leave none, and REQ-k6kcgd's delivery then reports
`NoAddress` for every round until the 7 days pass. This requirement is the
answer the owner ruled (Q1 (c)): no Wire change; Networked mode dials by the key alone,
as org-io's send path already does for a recipient with no kept address
(LLR-34tfm8). REQ-k6kcgd's "with no relay" is ruling D7's "no other Device
forwards it": a dial by key may use iroh's relay server, which D7 allows.
The alternatives the owner did not take are in the plan's Q1; the Loopback
residual stands.

*Note 2026-11-04 (change `worktree-org-io-publish-2`, task q1r; owner
ruling Q1' of 2026-11-04; a clarification, the ID is kept):* "by its Device
key alone" is a dial with no socket, made from an endpoint of the Persona's
own identity bound for it with iroh's relay server and address lookup,
which a direct-only endpoint lacks: without them the key can never be
found. A kept address that does not parse is no address that may be
dialled. Every dial that has an address stays direct (LLR-spckm6); no other Device forwards the acknowledgement
(ruling D7).
