## Under SDD-rmbr3t — The command surface

**LLR-ekz4zn**: `reconcile_organisations` takes no argument, locks the
org-io handle, calls `OrgIo::reconcile_held` once, and returns one entry per
result org-io reports, in org-io's order, each an object tagged by
`result` — `in_step` (`org_id`, `epoch`), `committed` (`org_id`, `epoch`,
`recipients` as hexadecimal DevicePublicKeys), `behind` (`org_id`,
`chain_epoch`), `removed` (`org_id`), `refused` (`org_id`, `reason`) or
`unverified` (`org_id`, `reason`) — with `org_id` as 40 hexadecimal
characters and each reason org-io's text unchanged. It decides nothing of
its own: with the chain not configured, every held Organisation is returned
`unverified`; with none held, the list is empty. The command body is
`commands::reconcile_all`.
satisfies: REQ-363366

Normal: `reconcile_all_reports_in_step_and_lists_the_organisation_verified`,
`each_reconciliation_crosses_ipc_tagged_with_its_fields` (reconcile).
Abnormal: `reconcile_all_over_an_unreadable_chain_reports_unverified_with_the_reason`
(reconcile);
`reconcile_organisations_with_the_chain_not_configured_reports_every_organisation_unverified`,
`reconcile_organisations_on_an_empty_store_reports_nothing` (ipc).

**LLR-8axx7h**: each Organisation `list_orgs` returns carries

entry are unchanged.
